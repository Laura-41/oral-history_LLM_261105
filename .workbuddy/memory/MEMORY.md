## 一、运行方式约定（研究者 2026-11-06 明确要求，最高优先）

**大批量跑语料时，助手不代为在对话里长时间运行，只给出可直接复制到终端的执行命令，由研究者自己在本地终端启动。**

研究者原话要点：「如果是大批量跑语料，你给我执行命令，我自己在终端开始，也方便我关注进度，防止我和你的对话窗口过长」，并要求「把这个要求记忆在整个工程里」。

执行细则：

1. 凡需大量 API 调用、预计持续数分钟以上、或会持续输出长日志的批量任务，助手**先给命令**，不在助手侧启动长任务／后台任务，不把长篇运行日志贴回对话。
2. 助手可自行完成的短时操作：零 API 的 `--dry-run`、前置核对、单次最小连通验证（几十 Token）、读取已生成的汇总／结果做分析、文档与登记表整理。判断标准：不占用对话窗口、不产生长时间等待。
3. 验证链路是否真能跑通时，只用**一份文档**做端到端验证，不顺手把整批跑掉；每批放行仍需人工抽检 `experience_scope` 与逐字证据（SOP §6 熔断不变）。
4. 给出的命令必须可直接复制：含 `cd` 到工程根、实时可见的进度输出、日志落盘、失败即停与断点续跑说明。
