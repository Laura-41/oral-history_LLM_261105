# 节点、标签、属性和关系的通俗说明

> 当前版本：v1.0  
> 更新日期：2026-11-05  
> 用途：用真实Demo解释模型JSON、人工标注和Neo4j图谱之间的关系。

## 一、先记住一句话

> **节点是卡片，标签是卡片种类，属性是卡片上的填空，关系是卡片之间的箭头，关系属性说明这个箭头具体是什么意思。**

可以想象桌上摆着许多小卡片：

- 一张卡片写“陈海峰”；
- 一张卡片写“到上海荣华印书馆当排字学徒”；
- 一张卡片写“荣华印书馆”；
- 一张卡片写“上海”；
- 一张卡片保存口述史原话。

把它们用带名字的线连起来，就是一个最基本的知识图谱。

## 二、五个最容易混淆的词

### 2.1 节点：有自己身份证号的卡片

“陈海峰”是人物节点，“荣华印书馆”是机构节点，“到荣华印书馆当学徒”是事件节点。

需要单独命名、单独查询、被多处复用的东西，通常适合做节点。每个节点都应有稳定ID，这就像它的身份证号。

### 2.2 标签：卡片顶部的分类贴纸

标签只回答“这张卡片是哪一大类”：

- `Person`：人物；
- `Organization`：机构；
- `Place`：地点；
- `EventNode`：一级事件；
- `SourceSegment`：原文片段；
- `EventType`：六类过程的理论类型。

“陈海峰是一个 `Person`”，不等于“陈海峰永远是 `Actor`”。`Person` 是他这张卡片的类型；`Actor` 是他在某一件具体事情里扮演的角色。

### 2.3 属性：卡片上的填空题

事件卡片上可以写：

- `event_id = CHF-V1-E01`；
- `event_name = 陈海峰到上海荣华印书馆当排字学徒`；
- `review_status = MODEL_CANDIDATE`；
- `confidence = ...`。

这些值只是在描述这张事件卡片，所以叫属性。

### 2.4 关系：两张卡片之间的箭头

例如：

- 事件 ──`HAS_PARTICIPANT`──→ 陈海峰；
- 事件 ──`HAS_TYPE`──→ 物质过程；
- 事件 ──`HAS_SOURCE`──→ 原文片段；
- 事件 ──`HAS_CIRCUMSTANCE`──→ 上海。

关系回答“这两张卡片是怎么联系的”。

### 2.5 关系属性：写在箭头旁边的小注释

事件与陈海峰之间都叫 `HAS_PARTICIPANT`，但陈海峰在这一件事里是主动行事的人，所以在箭头上写 `role=Actor`。

事件连到上海时，箭头上写 `kind=DIRECTION`，意思是“他朝上海去”，不是笼统地说“上海是个地点”。

## 三、用DEMO-P01完整拆一次

原话证据是：

> 我才11岁，我就到上海去了，家里也比较困难，就去当学徒了。当什么学徒呢？是印书馆里面的排字工人，我只有11岁，冒充13岁。

模型先交出一张“候选事件申请表”：

- 事件名：陈海峰到上海荣华印书馆当排字学徒；
- 类型：物质过程 `MATERIAL`；
- 核心过程：当排字学徒；
- 参与者：“我”，规范化为“陈海峰”，角色为 `Actor`；
- 时间：11岁；
- 方向：上海；
- 地点：荣华印书馆；
- 方式：冒充13岁；
- 原因：家庭经济困难。

人工确认后，图谱不是把这段JSON原样塞进一个大格子，而是把它拆成卡片和箭头：

```text
[陈海峰：Person]
        ↑ HAS_PARTICIPANT {role: Actor}
[当排字学徒：EventNode] ── HAS_TYPE ──→ [物质：EventType]
        │
        ├─ HAS_CIRCUMSTANCE {kind: DIRECTION} ─→ [上海：Place]
        ├─ HAS_CIRCUMSTANCE {kind: LOCATION}  ─→ [荣华印书馆：Organization/Place]
        ├─ HAS_TIME ─→ [11岁／1931年：EventTime]
        └─ HAS_SOURCE {function: EVIDENCE} ─→ [S0015：SourceSegment]
```

## 四、`Actor`不是人的永久标签

同一个陈海峰，在不同事件里会扮演不同角色：

- “陈海峰去上海当学徒”：他是 `Actor`；
- “陈海峰看到队伍开进”：他是 `Senser`；
- “陈海峰说起这段经历”：他是 `Sayer`；
- “陈海峰笑了”：他是 `Behaver`。

所以，`Actor`、`Senser`、`Sayer`和`Behaver`应该写在“人物与某个事件之间的箭头”上，而不是永久贴在人物卡片上。

## 五、为什么“荣华印书馆”不应被硬塞成 `Scope`

旧Demo用 `Scope` 来表示“工作单位”，相当于把 `Scope` 当成了“其他相关东西”的杂物筐。但在冻结规则里，`Scope` 不是万能筐。

取消错误 `Scope` 并不是删掉印书馆，而是把它放回正确的抽屉：

- 它在事件中可以作为工作地点或环境；
- 它在实体层仍然是一个独立的机构节点；
- 后续还可建立“陈海峰在荣华印书馆工作”的实体关系。

信息没丢，只是换到正确抽屉。

## 六、原文、JSON、CSV和Neo4j是四个不同阶段

| 阶段 | 用人话说 | 当前项目中的作用 |
|---|---|---|
| 原文 | 录音的逐字记录 | 永远保留，不能被模型改写 |
| 模型JSON | 模型填的候选申请表 | 等待校验和人工复核 |
| CSV／规范JSON | 整理好的账本 | 一张表记节点，一张表记关系 |
| Neo4j | 把所有卡片和箭头组装起来 | 查询、展示、回到原文 |

模型输出 `MODEL_CANDIDATE` 只表示“模型认为可以这样标”，不表示它已经成为正式历史事实。

## 七、判断一个东西放哪里的笨办法

1. 它需要独立ID、会被多个事件复用、需要单独查询吗？是就做**节点**。
2. 它只是在描述某一张卡片吗？是就做**属性**。
3. 它表示两张卡片怎么联系吗？是就做**关系**。
4. 它只是解释这条关系中的角色或方式吗？是就做**关系属性**。

例如：陈海峰是节点，“陈海峰”是人物名属性，事件到陈海峰的线是 `HAS_PARTICIPANT`，这条线上的 `role=Actor` 是关系属性。

## 八、当前DEMO-P01告诉我们什么

这次运行已经证明：

1. 模型能输出合法JSON；
2. 输出通过Schema校验；
3. 原文证据能在输入片段中逐字找到；
4. 模型把事件判为物质过程，与人工旧Demo一致；
5. 模型没有再把荣华印书馆误标为 `Scope`；
6. 但它只输出了“11岁”，漏掉后文明示的“1931年”，所以仍需人工复核；
7. 模型输出的“荣华印书馆”还是环境字符串，后续实体规范化步骤要将它连接到正式机构节点。
