## 一、先解决「为什么我这边只有表格」

截图里那条查询写的是 `RETURN e.event_name, t.raw_text, t.precision, t.source_status` —— **返回的都是属性列，没有节点/关系/路径对象**，Neo4j Browser 就不会生成 Graph 视图，只剩 `Table` / `RAW`。

改法只有一句：**把属性列换成节点变量**，需要连线时把关系变量一起返回。

```text
// ❌ 只出表格（示意，不可单独执行）
RETURN e.event_name, t.raw_text;

// ✅ 出图（示意，不可单独执行）
RETURN d, r1, e, r2, t;
```

执行后结果面板左侧会自动出现 **Graph** 标签，点它即可。`Ctrl/⌘ + Enter` 执行，滚轮缩放，拖动排布，点节点在下方看全部属性。

其余三条通用约定：

| 项 | 说明 |
|---|---|
| `doc_id` | 存的是**语料 ID**（`YYS-04`、`CHF-V1-01`）；技术编号 `BATCH02-DOC09` 只出现在 `event_id` / `segment_id` 里，写 `d.doc_id='BATCH02-DOC09'` 一定返回空 |
| `LIMIT` | 全库有 2.7 万节点，不限制会卡死浏览器。下面每条都已给好安全上限，想看更多把数字调大即可 |
| 数据口径 | 6 份 `WORKFLOW_DEMO`／`CONFIRMED`（人工金标准，词表 v1.0）与 54 份 `BATCH_APPLICATION`／`MODEL_CANDIDATE`（模型候选，词表 v1.1）**统计不可相加**，查询请带 `WHERE d.data_role = '…'`，生平按 `episode_id STARTS WITH 'DEMO-'` 区分 |

## 三、B 组：人生链路（论文主线）

### B1 · 一位受访者的一生 · 人工金标准 18 站（19 节点 / 35 关系）

```cypher
MATCH (p:Entity:BiographicalSubject {entity_id:'PER-CHF'})-[h:HAS_LIFE_EPISODE]->(l:LifeEpisode)
WHERE l.episode_id STARTS WITH 'DEMO-'
OPTIONAL MATCH (l)-[n:BIOGRAPHICAL_NEXT]->(l2:LifeEpisode)
RETURN p, h, l, n, l2;
```

人物 → 18 个 `LifeEpisode`，粉色 `BIOGRAPHICAL_NEXT` 串成一条链。换人：`PER-CRT`（陈锐霆 15 站）、`PER-YYS`（杨永松 7 站）。
去掉 `WHERE` 那行＝看该人物全部生平（含 184 条正式线），但会太密；**口径提醒**：正式线两序同值、`historical_order` 是占位，不能当独立历史序用。

### B1+ · 人生链路加「文档层」—— 每一站属于哪个文件（40 节点 / 71 关系）★ 本次新增

B1 只有人物→站点，看不到来源。这条把**实际链路**整条画出来，层次是：

```
人物 (BiographicalSubject)
  └─HAS_LIFE_EPISODE→ 生平站点 (LifeEpisode)
        └─SUPPORTED_BY_EVENT→ 支撑事件 (EventNode)
              └─HAS_EVENT← 采访文档 (InterviewDocument)     ← 事件由哪份文档指过来
```

```cypher
MATCH (p:Entity:BiographicalSubject {entity_id:'PER-CHF'})-[h:HAS_LIFE_EPISODE]->(l:LifeEpisode)
WHERE l.episode_id STARTS WITH 'DEMO-'
MATCH (l)-[s:SUPPORTED_BY_EVENT]->(e:EventNode)<-[he:HAS_EVENT]-(d:InterviewDocument)
OPTIONAL MATCH (l)-[n:BIOGRAPHICAL_NEXT]->(l2:LifeEpisode)
RETURN p, h, l, s, e, he, d, n, l2;
```

实测 18 条链路铺到 **3 份文档**（`CHF-V1-01` / `CHF-V2-01` / `CHF-V3-01`），粉色 `BIOGRAPHICAL_NEXT` 保留站点顺序，橙色 `SUPPORTED_BY_EVENT` 和 `HAS_EVENT` 就是截图里那两种灰色关系标签。换人改 `entity_id`；去掉 `WHERE` 那行＝看该人物全部生平（含正式线 184 站，会密得多）。全库 377 条生平**全部**有支撑事件、且事件都能回溯到文档，不会断链。

**想直接读「属于哪个文件」用表格版**（`d.title` 即 docx 文件名去扩展名，`d.doc_id` 是语料 ID）：

```cypher
MATCH (p:Entity:BiographicalSubject {entity_id:'PER-CHF'})-[:HAS_LIFE_EPISODE]->(l:LifeEpisode)-[:SUPPORTED_BY_EVENT]->(e:EventNode)<-[:HAS_EVENT]-(d:InterviewDocument)
WHERE l.episode_id STARTS WITH 'DEMO-'
RETURN l.life_order AS 序, l.episode_name AS 生平站点, d.doc_id AS 语料ID, d.title AS 文件名, e.event_name AS 支撑事件
ORDER BY l.life_order;
```

前 7 站在 `陈海峰一访01`（`CHF-V1-01`），第 8 站起跳到 `陈海峰三访01`（`CHF-V3-01`）—— 正好对应截图里「八一三事变后…」那一簇和右侧另一簇。

**再往下加两层**（二级阶段 + 逐字片段，57 节点 / 62 关系；前 8 站，去掉 `LIMIT 8` 会涨到 113 节点）：

```cypher
MATCH (p:Entity:BiographicalSubject {entity_id:'PER-CHF'})-[h:HAS_LIFE_EPISODE]->(l:LifeEpisode)
WHERE l.episode_id STARTS WITH 'DEMO-'
MATCH (l)-[s:SUPPORTED_BY_EVENT]->(e:EventNode)<-[he:HAS_EVENT]-(d:InterviewDocument)
WITH p, h, l, s, e, he, d ORDER BY l.life_order LIMIT 8
OPTIONAL MATCH (e)-[hs:HAS_STAGE]->(st:ProcessStage)
OPTIONAL MATCH (e)-[ht:HAS_TIME]->(t:EventTime)-[sb:SUPPORTED_BY]->(seg:SourceSegment)
RETURN p,h,l,s,e,he,d,hs,st,ht,t,sb,seg LIMIT 30;
```

### B2 · 时间切片 · 1937–1940 年这一段（36 节点 / 67 关系）

```cypher
MATCH (p:Entity:BiographicalSubject {entity_id:'PER-CHF'})-[h:HAS_LIFE_EPISODE]->(l:LifeEpisode)
WHERE l.normalized_start >= '1937' AND l.normalized_start < '1940'
OPTIONAL MATCH (l)-[n:BIOGRAPHICAL_NEXT]->(l2:LifeEpisode)
```

按年份切一段出来放大看，适合做「抗战初期」这类个案图。全库有 ISO 归一值的生平 135 条，年份范围 1914–1984；改两个年份边界即可换段。

**P2 · 人物 + 关系 + 别名 + 全部采访文档**（23 节点 / 23 关系）

```cypher
MATCH (p:Entity:BiographicalSubject {entity_id:'PER-CHF'})
OPTIONAL MATCH (p)-[r:RELATED_TO]-(o:Entity)
OPTIONAL MATCH (al:EntityAlias)-[a:ALIAS_OF]->(p)
```

### 6.2 文档为中心

**F1 · 一份文档的事件全展开（时间／二级阶段／参与者／环境成分）**（31 节点 / 29 关系）

```cypher
MATCH (d:InterviewDocument {doc_id:'YYS-04'})-[:INTERVIEW_OF]->(p:Entity:BiographicalSubject)
MATCH (d)-[he:HAS_EVENT]->(e:EventNode)
WITH d, p, he, e ORDER BY e.narrative_order LIMIT 3
OPTIONAL MATCH (e)-[ht:HAS_TIME]->(t:EventTime)
OPTIONAL MATCH (e)-[hs:HAS_STAGE]->(st:ProcessStage)
OPTIONAL MATCH (e)-[hp:HAS_PARTICIPANT]->(x:Entity)
OPTIONAL MATCH (e)-[hc:HAS_CIRCUMSTANCE]->(c:Circumstance)
RETURN d, p, he, e, ht, t, hs, st, hp, x, hc, c;
```

`WITH ... LIMIT 3` 是**先取前 3 个一级事件再展开**，否则 12 事件 × 阶段／参与者会爆到上百节点；想多看改成 `LIMIT 5`。`Circumstance` 点开看 `kind` / `value_text`，就是 D5 裁决后的 5 类环境成分。

**F2 · 文档语料层：片段 → 时间表达／实体提及／来源附件**（33 节点 / 32 关系）

```cypher
MATCH (d:InterviewDocument {doc_id:'YYS-04'})-[hs:HAS_SEGMENT]->(s:SourceSegment)
WITH d, hs, s ORDER BY s.segment_order LIMIT 5
OPTIONAL MATCH (s)-[hte:HAS_TIME_EXPRESSION]->(te:TimeExpression)
OPTIONAL MATCH (s)-[hm:HAS_MENTION]->(m:EntityMention)-[mn:MENTIONS]->(x:Entity)
OPTIONAL MATCH (s)-[ha:HAS_ATTACHMENT]->(att:SourceAttachment)
RETURN d, hs, s, hte, te, hm, m, mn, x, ha, att;
```

这条走的是**逐字语料**而不是事件：点 `SourceSegment` 看 `verbatim_text` 原话、`segment_type`（含 `RECORDING_TIMESTAMP`）；`SourceAttachment.function` 可核对编者注是否被误当史实（应为 `DOCUMENT_ONLY` / `INTERVIEWER_PROMPT`，不是 `EVIDENCE`）。

### 6.3 一级事件 / 二级阶段展开

**E1 · 单个一级事件全展开**（11 节点 / 11 关系，最干净的一张）

```cypher
MATCH (d:InterviewDocument)-[he:HAS_EVENT]->(e:EventNode {event_id:'BATCH02-DOC09-DE007'})
OPTIONAL MATCH (e)-[ht:HAS_TIME]->(t:EventTime)-[sb:SUPPORTED_BY]->(seg:SourceSegment)
OPTIONAL MATCH (e)-[hs:HAS_STAGE]->(st:ProcessStage)
OPTIONAL MATCH (st)-[ns:NEXT_STAGE]->(st2:ProcessStage)
OPTIONAL MATCH (e)-[hp:HAS_PARTICIPANT]->(x:Entity)
OPTIONAL MATCH (e)-[hc:HAS_CIRCUMSTANCE]->(c:Circumstance)
OPTIONAL MATCH (e)-[hty:HAS_TYPE]->(ty:EventType)
RETURN d,he,e,ht,t,sb,seg,hs,st,ns,st2,hp,x,hc,c,hty,ty;
```

**一级事件 = `EventNode`（`event_name`），二级阶段 = `ProcessStage`（`stage_summary` / `process_text`）**，两者是 `HAS_STAGE` 直连，不是父子事件。换 `event_id` 即可看任意事件；这一条同时给出文档、逐字证据、阶段链、参与者、环境成分、事件类型，适合当论文里的个案图。

**E2 · 一级事件序列 + 每个事件的二级阶段同图**（21 节点 / 23 关系）

```cypher
MATCH (d:InterviewDocument {doc_id:'YYS-04'})-[he:HAS_EVENT]->(e:EventNode)
WITH d, he, e ORDER BY e.narrative_order LIMIT 4
OPTIONAL MATCH (e)-[hs:HAS_STAGE]->(st:ProcessStage)
OPTIONAL MATCH (e)-[n:NEXT]->(e2:EventNode)
RETURN d, he, e, hs, st, n, e2;
```

红色 `NEXT` 串一级事件、每个事件下面挂一串蓝色阶段 —— 一眼看出「一级／二级」两层怎么叠。C1（纯 `NEXT` 链）、C2（纯阶段链）是它的拆解版。

### 6.4 实体查询

### 6.5 Z1 · 截图那种多类节点网络图（40 节点 / 56 关系）

```cypher
MATCH (p:Entity:BiographicalSubject {entity_id:'PER-CHF'})<-[io:INTERVIEW_OF]-(d:InterviewDocument)
WHERE d.data_role='WORKFLOW_DEMO'
MATCH (d)-[he:HAS_EVENT]->(e:EventNode)<-[s:SUPPORTED_BY_EVENT]-(l:LifeEpisode)
OPTIONAL MATCH (l)-[bn:BIOGRAPHICAL_NEXT]->(l2:LifeEpisode)
RETURN p, io, d, he, e, s, l, bn, l2 LIMIT 45;
```

和截图同构：**中间人物 / 青色文档 / 橙绿两色生平站点与支撑事件**，`HAS_EVENT` 从文档指向事件、`SUPPORTED_BY_EVENT` 从站点指向事件、`BIOGRAPHICAL_NEXT` 串站点。截图里「八一三事变后…」「组织篁村人民抗日救亡会…」就是 `l.episode_name` / `e.event_name`。配色见下一节的「白底截图风格」，导出 PNG 前把 Browser 切成 Light 主题可得到白底。

### 白底截图风格（复现你给的那张图）

你截图里是**白底 + 深色字 + 橙／绿／青／红四类圆点 + 灰色关系小字**。做法是：Browser 左下角设置里切到 **Light 主题**（导出 PNG/SVG 才是白底），再在 `:style` 里粘这段：

```grass

node.ProcessStage { color: #A8D8E8; caption: '{stage_id}'; }
node.Entity { color: #B0BEC5; caption: '{canonical_name}'; }
node.EventTime { color: #B39DDB; caption: '{raw_text}'; }
```

`caption: '{title}'` 会让青色文档节点直接显示「陈海峰一访01」这类文件名，和截图一致；站点／事件用 `episode_name` / `event_name`，两个名字常相同，靠颜色区分。
