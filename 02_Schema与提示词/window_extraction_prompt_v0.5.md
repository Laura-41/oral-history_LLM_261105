# 连续窗口盲抽取提示词 v0.5

本提示词用于连续访谈窗口中的一级经历抽取。它是独立版本，不依赖此前的窗口规则文件。事件类型、参与者角色、规范化和逐字证据继续遵守系统提示词v0.3。

## 1. 一级事件单位

一级事件表示受访者或核心人物的一次完整经历，不等于一个动词、一句话、一种过程类型或一个严重细节。先识别人物经历主线，再把触发、行动、遭遇、应对和结果组织成适当粒度的事件。

每个一级事件应具有可独立查询的核心目标或阶段性结果。感知、听说、看到、情绪变化、生活细节和他人遭遇如果只承担触发、阶段、原因或结果功能，通常不单独建立事件节点。

## 2. 应当合并的情况

相邻内容满足以下多数条件时，应合并为一个一级事件：

1. 核心参与者基本相同；
2. 时间、地点和叙事阶段连续；
3. 前一过程触发或推动后一过程；
4. 多个过程共同指向同一个核心行动或阶段性结果；
5. 某个过程单独抽出后，只能说明“为什么发生后面的行动”，不能完整说明受访者完成了什么经历。

典型结构“背景／触发—行动—遭遇—应对—结果／影响”通常合并为一次完整经历。

他人遭遇即使严重或包含死亡，也不自动成为独立节点。如果它主要解释受访者为何反抗、离开、参军或改变选择，应与前面的持续背景或后面的受访者行动合并。严重程度不能代替边界判断。

同一突发经历内部的“听说消息—前往查看—遭遇危险—逃脱—形成心理影响”应合并，不拆成多个一级事件。

## 3. 应当分开的情况

即使人物和时空大体连续，出现以下情况时也应开始新的一级事件：

1. 前一段已经形成可独立概括的稳定经历或阶段性结果；
2. 叙述从长期、反复、日常状态转入一次性、突发遭遇；
3. 核心目标发生明显变化；
4. 新的外部施事者介入并造成新的结果；
5. 后一段删去前一段后，仍能独立构成有触发、过程和结果的完整人物经历。

“同一年龄、地点邻近、叙述相邻”不能单独作为合并理由。不得只保留窗口中最显著的最终遭遇，而吞并此前已经完整成立的长期经历。

## 4. 中等粒度原则

采用中等粒度：既不把每个动作和心理变化都升级为事件，也不把结果不同的整段人生经历压成一个节点。

示例一：长期从事家庭劳动已经形成稳定生活阶段，随后因新消息去观看外来事物并遭遇突发攻击。前者与后者应分为两个一级事件；后者内部的听说、前往、观看、受袭、逃脱和心理影响合并。

示例二：长期受压迫、同伴受害、提出意见受阻，继而组织集体反抗并离开原单位。这些内容共同解释同一次反抗行动，优先合并为一个一级事件，不把同伴受害单独建节点。离开后经历一段失业困苦并最终重新就业，优先合并为另一个“失业后再就业”事件；如果原文明确突出两个独立阶段，也允许分开，但不得继续拆分生活细节。

## 5. 背景排除

优先抽取受访者或核心人物亲历、参与、感知或明确受到影响的经历。仅用于交代时代、地点或原因的外部历史事实，不单独升级为一级事件，除非窗口明确以该事实本身为叙述中心。

编辑时间标记、采访者提示及未进入人物经历主线的背景片段写入 `unassigned_segment_ids`。

## 6. 输出前自检

1. 每个候选是否具有独立的核心目标或阶段性结果？
2. 它是否只是另一个候选的原因、触发、感知、阶段或心理结果？如果是，应合并。
3. 是否把同一因果链中的小过程拆成多个节点？如果是，应合并。
4. 是否把两个结果明显不同的完整经历压成一个节点？如果是，应分开。
5. 是否把背景历史事实误当成受访者经历？如果是，应排除。

## 7. 窗口输出规则

1. 输入是按原顺序排列的连续访谈片段，事件数量和边界未知。
2. `source_segment_ids` 列出构成该完整经历的直接原文片段，按输入顺序排列；同一过渡片段可以支持相邻事件。
3. 每个输入片段ID必须至少出现在某个事件的 `source_segment_ids` 或 `unassigned_segment_ids` 中。
4. 每个候选内部的 `event` 对象必须遵守单事件Schema v1.0；`evidence_quote` 必须逐字来自该候选的某个 `source_segment_ids`。
5. `candidate_id` 依次使用 `<window_id>-E01`、`<window_id>-E02`。
6. 只输出合法JSON对象，不输出Markdown或解释性前言。

```json
{
  "window_id": "",
  "events": [
    {
      "candidate_id": "",
      "source_segment_ids": [],
      "event": {
        "event_name": "",
        "event_type": "MATERIAL",
        "event_type_zh": "物质",
        "core_process": "",
        "participants": [],
        "circumstances": [],
        "projected_content": null,
        "evidence_quote": "",
        "type_basis": "",
        "alternative_event_type": null,
        "ambiguity_reason": null,
        "review_status": "MODEL_CANDIDATE"
      }
    }
  ],
  "unassigned_segment_ids": []
}
```

没有事件时，`events` 输出空数组，并将全部片段ID写入 `unassigned_segment_ids`。
