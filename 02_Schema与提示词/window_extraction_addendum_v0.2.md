# 连续窗口盲抽取边界规则 v0.2

本规则用于连续窗口中的一级经历抽取。除事件边界和窗口输出结构外，事件类型、参与者角色、规范化及证据要求继续遵守系统提示词v0.3。

## 1. 一级事件的判定单位

一级事件表示受访者或核心人物的一次完整经历，而不是一个动词、一句话或一种过程类型。先识别人物经历主线，再在主线内部判断阶段。

如果相邻内容同时满足以下多数条件，应合并为一个一级事件：

1. 核心参与者基本相同；
2. 时间和地点连续，未发生明显跳转；
3. 前一过程触发或推动后一过程；
4. 多个过程共同指向同一个阶段性结果；
5. 单独抽出某个感知、情绪或动作后，无法完整表达这次经历的意义。

典型结构“背景／触发—行动—遭遇—应对—结果／影响”通常是一条完整经历。感知、听说、看到、心理感受和情绪变化如果只是这条经历的触发、阶段或结果，不得升级为并列一级事件。

例如，“听说敌舰—跑去观看—遭到炮击—逃脱—产生仇恨”应合并为一次完整经历；其中听说、看到、开炮、逃脱和仇恨是同一事件链中的阶段，不是五个一级事件。

只有在人物、时间、地点、目标或阶段性结果发生明显转换时，才开始新的一级事件。

## 2. 背景排除

优先抽取受访者或核心人物亲历、参与、感知或明确受到影响的经历。用于交代时代背景、地点背景或原因的外部历史事实，不单独升级为一级事件，除非窗口明确以该历史事实本身为叙述中心。

例如，受访者讲童年经历时顺带提到“某方攻打青岛”，该内容用于交代背景，不应与受访者的童年经历并列为一级事件。

编辑时间标记、采访者提示及未进入人物经历主线的背景片段写入 `unassigned_segment_ids`。

## 3. 输出前边界自检

对每个候选事件逐项检查：

1. 它是否表达一段有起因、过程或结果的完整人物经历？
2. 它是否只是另一个候选的触发、阶段、感知或心理结果？如果是，应合并。
3. 它是否只是时代背景或外部历史事实？如果是，应不抽取。
4. 相邻候选能否用“因此、随后、结果”连成同一条因果链？如果能且人物、时空连续，应合并。
5. 合并后再选择整件经历的主导事件类型；其他过程保留在事件名称、核心过程概括或证据片段中，不另建一级事件。

## 4. 窗口输出结构

1. 输入是一段按原顺序排列的连续访谈片段，事件数量和边界未知。
2. `source_segment_ids` 列出构成该完整经历的直接原文片段，按输入顺序排列；同一过渡片段可同时支持相邻事件。
3. 每个输入片段ID必须至少出现在某个事件的 `source_segment_ids` 或 `unassigned_segment_ids` 中。
4. 每个候选内部的 `event` 对象必须遵守单事件Schema v1.0；`evidence_quote` 必须逐字来自该候选的某个 `source_segment_ids`。
5. 只输出以下合法JSON对象，不输出Markdown或解释性前言：

```json
{
  "window_id": "",
  "events": [
    {
      "candidate_id": "",
      "source_segment_ids": [],
      "event": {
        "event_name": "",
        "event_type": "MATERIAL",
        "event_type_zh": "物质",
        "core_process": "",
        "participants": [],
        "circumstances": [],
        "projected_content": null,
        "evidence_quote": "",
        "type_basis": "",
        "alternative_event_type": null,
        "ambiguity_reason": null,
        "review_status": "MODEL_CANDIDATE"
      }
    }
  ],
  "unassigned_segment_ids": []
}
```

`candidate_id` 依次使用 `<window_id>-E01`、`<window_id>-E02`。没有事件时，`events` 输出空数组，并将全部片段ID写入 `unassigned_segment_ids`。
