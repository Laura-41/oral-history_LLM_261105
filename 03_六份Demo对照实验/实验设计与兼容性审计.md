# 六份Demo模型对照实验设计与兼容性审计

> 版本：v1.0  
> 日期：2026-11-05  
> 数据角色：`WORKFLOW_DEMO`  
> 目的：验证模型标注工作流、结构稳定性和原文可追溯性，不把六份Demo冒充独立测试金标准

## 一、数据规模

六份Demo共包含：

- 6份访谈文档；
- 689个原文片段；
- 40个一级事件；
- 119个二级阶段；
- 原文挂接覆盖率均为1.0000。

一级事件类型分布：

| 类型 | 数量 |
|---|---:|
| 物质 | 31 |
| 心理 | 5 |
| 关系 | 4 |
| 言语 | 0 |
| 行为 | 0 |
| 存在 | 0 |

因此，六份Demo不能单独评价六类过程的完整识别能力。言语、行为、存在及六类边界继续由15个冻结开发用例覆盖；Demo主要检验真实口述史片段中的复杂表达、证据保真和工作流。

## 二、旧版标注与冻结Schema的兼容性

原Demo必须保持不变，但它形成于本轮理论角色收紧之前。审计发现：

- 8条旧版 `Scope` 实际是工作单位、劳动对象、任职／训练／实习／学习机构；按冻结提示词v0.3不能直接作为 `Scope` 金标准；
- 1个心理事件包含旧版 `Actor`，不属于心理过程封闭角色词表；
- 其余旧角色名称均在当前类型允许词表内，但具体角色合理性仍需结合原文人工复核。

处理原则：不回写、不覆盖六份Demo；事件类型可以直接比较，角色字段先报告模型输出和旧版标注的差异，再按冻结操作性定义人工裁决。论文中不得把旧版角色的机械一致率直接称为角色准确率。

## 三、分阶段实验

### 3.1 受控事件重建

每份文档按 `narrative_order` 选取第一个人工确认事件，共6个事件包。每个包只向模型提供该事件的原文证据片段、片段ID、文档信息和受访者，不提供人工事件名称、类型、过程、参与者或事件ID。

该阶段明确给定事件边界，评价：

- API与JSON稳定性；
- Schema核心约束；
- 证据能否逐字定位到输入片段；
- 事件类型；
- 核心过程；
- 参与者与环境的理论合理性；
- Token、耗时和费用。

该阶段不评价模型自主发现事件边界的能力。

### 3.2 连续窗口盲抽取

受控事件重建稳定后，从每份文档选择连续SourceSegment窗口，只提供原文和片段ID，由模型自主决定事件数量、边界和证据片段。此阶段才评价事件数量偏差、边界、非事件内容排除和片段覆盖。

### 3.3 六份全文分块运行

连续窗口稳定后，按片段ID、话题和长度分块运行六份全文，再进行窗口间去重、文档级事件合并、历史顺序、阶段、时间、实体和覆盖审计。不得把整篇访谈一次提交后只接受模型摘要。

## 四、输入与答案隔离

目录结构：

```text
01_受控事件包/
├── inputs/                 # 可发送给模型
├── answer_key/             # 只在模型完成后评分，禁止进入API输入
├── manifest.csv
└── results/
```

生成程序只把 `inputs/` 中的内容送入模型。`answer_key/answer_key.json` 明确标记为评分专用。模型结果文件不含API密钥，也不复制人工答案。

## 五、首轮运行顺序

1. 先用DeepSeek运行 `DEMO-P01`，人工检查提示词和证据引用；
2. 通过后运行DeepSeek其余5包；
3. 使用完全相同的6包运行Qwen；
4. 完成技术指标和人工对照表；
5. 不根据单个模型结果修改冻结提示词，错误只登记；如需修订则另建版本并重新回归。

## 六、DeepSeek六包运行状态

2026-11-05已使用DeepSeek完成全部6个受控事件包：

- 合法JSON 6／6，逐字证据定位6／6，Schema技术通过5／6；
- P03因物质事件缺少`Actor`而技术失败，失败结果原样保留；
- 与人工旧Demo严格同类5／6；P04旧标为关系过程，模型以“统一指挥”的行动视角标为物质过程，属于需人工裁决的建模分歧，不能把严格一致数直接解释为准确率；
- P02、P04和P06均出现复合事件被收窄为部分子过程，P06只保留最终“集结”；
- 六包均显示单个逐字引文不能完整支撑所有字段，后续需增加字段级多证据和片段覆盖质检；
- 累计82423 Token，估算费用¥0.271141，平均首Token时间约120.440秒；
- 冻结提示词和Schema保持不变；Qwen同包对照因学校平台接口持续超时而暂缓，不把接口失败解释为模型能力失败；
- 详细逐包结果见`01_受控事件包/测试记录.md`。

### 6.1 Qwen对照暂缓说明

2026-11-05，模型列表仍可见 `cuc/qwen`，且同期 `cuc/deepseek` 最小请求正常，但Qwen最小请求和受控事件包请求持续读取超时，未生成六包结果。此前Qwen最小测试和六类标准单句测试已经成功，故当前仅登记接口可用性异常。服务恢复后仍使用相同六包补跑；在此之前，不报告Qwen与DeepSeek在真实Demo上的质量比较。

为控制规模，连续窗口阶段只使用一个最小窗口：固定选取 `CRT-01-S0018` 至 `CRT-01-S0027` 共10个片段，用一次DeepSeek请求验证模型能否自主识别两个相邻事件。该次请求已经完成；根据下述边界结果，当前不扩展六份全文分块，也不批量处理其余54份。

### 6.2 连续窗口最小验证结果

2026-11-05已用DeepSeek完成一次最小连续窗口盲抽取。JSON、单事件Schema、逐字证据和10个输入片段覆盖均通过，但模型抽取6个事件，人工参考为2个：第1个人工事件边界完整恢复，第2个经历被拆成4个候选，另把背景中的“攻打青岛”提升为候选事件。结果判为“技术通过、一级事件边界过度切分失败”。

因此当前不扩展更多窗口，不进入六份全文分块或54份批量处理。若以后继续，需要另建边界规则版本，重点约束人物经历主线、共同目标、阶段性结果和背景排除，再用同一窗口回归。

### 6.3 v0.3回归与第二窗口泛化

边界规则v0.3在 `WINDOW-01` 上抽取2个事件，事件数量、片段边界和主导类型均与人工参考一致。随后仅增加一个来自另一份访谈的 `WINDOW-02` 进行泛化检查。

`WINDOW-02` 技术结构通过，但模型抽取5个事件，人工参考为2个。模型分别保留资本家剥削、富康受虐死亡、组织罢工离厂、失业困苦和重新就业，均有直接原文依据；人工参考将前三项合并为罢工事件，将后两项合并为失业与再就业事件。该结果既说明v0.3未稳定复现人工粒度，也提示旧人工一级事件可能偏宽。

因此停止针对单个窗口继续调参，不执行六份全文分块或剩余54份批量处理。后续若恢复，应先由研究者或导师明确一级事件的查询粒度和合并准则，再决定采用人工宽边界还是模型较细边界。

### 6.4 独立提示词v0.5双窗口结果

研究者确定中等粒度：首窗口必须保持2个事件；第二窗口最佳为2个，也接受3—4个，但富康受虐死亡不得单独成为节点。基于该标准建立独立提示词v0.5，不依赖旧增量规则文件。

2026-11-06双窗口回归均达到最佳结果：`WINDOW-01`输出2个事件，两个片段边界与参考完全一致；`WINDOW-02`输出2个事件，将富康受虐并入罢工经历，并将失业困苦与重新就业合并为第二段完整经历。两份JSON、Schema、逐字证据和输入片段覆盖均通过。

该结果支持v0.5在当前两个小窗口上的边界可用性，但样本仍不足以代表全文或其余54份。根据研究者指令，第5步暂不执行。

### 6.5 第三窗口便利抽样

从另一份杨永松访谈直接抽取 `S0020—S0030` 共11个连续片段，不按预期事件数量优化。模型识别3个事件：前两个对应人工完整事件，第三个对应下一事件在窗口末尾的部分开头。

第三个候选有直接原文依据，不属于事实幻觉；但后续过程位于窗口外，模型仍按普通完整候选输出，没有设置 `NEEDS_REVIEW`。同时，第2个事件偏重换帽，对誓师开赴前线的整体结果概括不足。结果判为技术通过、完整事件基本识别、窗口边缘截断处理失败。

第三窗口的截断候选说明全文处理必须采用重叠窗口和跨窗口合并，但不要求继续修改v0.5。研究者基于时间成本决定跳过六份Demo全文验证，直接把剩余54份中的3份作为正式熔断批次；窗口末尾候选由确定性后处理标为`NEEDS_REVIEW`并带入下一窗口合并。

### 6.6 正式批处理决策

正式批处理不一次性提交54份。首批从六份Demo之外选择三位受访者各1份，结果本身计入54份正式产出。首批满足JSON、Schema、片段覆盖、边缘合并和背景排除条件后，其余51份按每批9份继续；任一批触发熔断条件即暂停，不覆盖已完成结果。

这一调整省略的是“六份旧Demo全文重复验证”，不是省略质量控制。三个窗口仍不足以支持正式准确率结论，54份输出继续保持候选状态并接受自动校验、人工抽检和争议复核。详细顺序见`04_54份正式语料批处理/README.md`。
