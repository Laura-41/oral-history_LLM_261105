# 文档级归并与经历范围分类

> 版本：v0.6
> 日期：2026-11-06  
> 状态：DeepSeek首批3份均已通过；Qwen的DOC03窗口抽取与文档级归并已技术通过，核心反证生效，但存在1项范围分类与冻结契约相悖，待研究者裁决，暂不继续DOC01、DOC02。

## 一、为什么增加这一层

第一阶段重叠窗口抽取已稳定实现JSON、单事件Schema、证据ID和片段覆盖率控制，但它不能单独完成：

1. 同一事件在相邻窗口的去重与归并；
2. 受访者个人经历与部队历史、他人行动、转述背景的区分；
3. 一个混合候选内部的个人经历与讲述背景拆分；
4. 文档末尾候选的完整性复核。

本层只生成新结果，不覆盖第一阶段原始响应和窗口候选。

## 二、已准备文件

- `inputs/`：首批3份文档级输入包；
- `manifest.csv`：输入规模和候选数统计；
- `../../02_Schema与提示词/document_consolidation_prompt_v0.1.md`：归并与范围规则；
- `../../02_Schema与提示词/document_consolidation_schema_v1.0.json`：第二阶段输出Schema；
- `../../02_Schema与提示词/document_consolidation_output_contract_v0.3.md`：精确输出字段契约及内容回归补充规则；
- `../../scripts/prepare_document_consolidation.py`：不调用API的输入准备程序；
- `../../scripts/run_document_consolidation.py`：逐文档运行程序；
- `../../scripts/validate_document_consolidation.py`：候选覆盖、证据和范围硬校验。
- `../../scripts/normalize_document_consolidation.py`：对已知的等价字段结构执行无损规范化；
- `../../scripts/recover_document_consolidation.py`：从已保存原始响应恢复技术通过结果，不再调用API。

输入包保留全部受访者和采访者对话，排除人物小传、录音时间码和脚注，避免用编辑材料推测受访者在场。

## 四、输出核心字段

- `document_events`：归并或拆分后的文档级事件；
- `candidate_decisions`：每个窗口候选的唯一去向；
- `experience_scope`：`PERSONAL_EXPERIENCE / NARRATED_CONTEXT / UNCERTAIN`；
- `participation_bases`：本人直接参与、集体且有任务、听他人转述、明确未参加等依据；
- `scope_evidence_segment_ids / scope_evidence_quote`：范围判断的逐字原文证据；
- `completeness`：`COMPLETE / INCOMPLETE / UNCERTAIN`；
- `canonical_event`：继续遵守六类过程单事件Schema。

校验器要求所有输入候选恰好有一条决策记录；个人经历必须具有本人直接参与、直接受影响或集体中明确任务依据。

## 五、v0.1试运行结果

`BATCH01-DOC03`第一次文档级试运行返回合法JSON，但模型使用了与Schema语义等价的自定义字段。原始响应保留不变；兼容层只执行字段映射和嵌套，不修改任何归并、范围或事件内容。规范化后：

- 10/10个输入候选均有唯一决策记录；
- 生成8个文档级事件：`PERSONAL_EXPERIENCE` 4个，`NARRATED_CONTEXT` 4个；
- 成功使用`S0026`中「我不在现场」「我讲这些东西我不参加」阻止前线进攻、减员和夜攻进入个人经历链；
- 成功保留动员新兵和往前查看后返回等本人经历；
- 保留缴获武器组建第三团被判为非独立事件。

内容回归尚未通过：

1. `W002-E01`的平型关进攻与`W003-E01`的同一战斗减员结果没有归并；
2. 「参加政治组会议并接受任务」的范围证据只引用一般性会议表述，没有直接引用`S0021`中「把我……协助民运股工作」；
3. 「他教我们喊话」被标为`COLLECTIVE_WITH_ROLE`，但当前原文没有给出杨永松在该教学事件中的具体职务或个人行动。

详细抽检见`review/BATCH01-DOC03_v0.1_抽检.md`。

v0.2复跑直接输出正式Schema，未使用兼容转换；10个输入候选归并／拆分为7个文档级事件，个人3个、背景4个、待复核2个。v0.1的3项定向问题全部修正，详见`review/BATCH01-DOC03_v0.2_抽检.md`。

`BATCH01-DOC01`使用v0.2运行后，13个候选形成9个文档事件，4组语义重复均正确归并，技术结构和逐字证据全部通过。但范围分类出现2处过度保守：模型把「我们就和新四军接上头了、所在部队被改编」和「我们都去、部队打游击」降为讲述背景。详细判断见`review/BATCH01-DOC01_v0.2_抽检.md`。

v0.3复跑仍形成9个文档事件，个人经历由5个增至7个、背景由4个降至2个；「我们接头」和「我们都去打游击」均使用直接集体动作证据恢复为个人经历，部队长期沿革和新四军整体壮大仍保持为背景。技术与内容回归通过，详见`review/BATCH01-DOC01_v0.3_抽检.md`。

## 六、首批回归结论与下一步

v0.3保留v0.2的全部硬约束，并用明确集体动作与组织直接受影响的窄定义修正范围分类过度保守。首批3份全部通过：31个窗口候选形成24个文档事件，个人16个、背景7个、不确定1个、待复核4个。

`BATCH01-DOC02`的1个不确定和2个待复核属于正确风险控制：菏泽守城的具体单位指代需人工核对；文末袭击只有准备、没有受访者参与证据和结果。详见`review/BATCH01-DOC02_v0.3_抽检.md`。

当前文档级提示词、输出契约、Schema和校验器已记录SHA-256并冻结，见`../../02_Schema与提示词/文档级归并第一版冻结清单.md`。

双模型文件现已隔离。Qwen不能复用DeepSeek的文档级输入包，因为其中包含DeepSeek生成的窗口候选；必须先完成Qwen窗口抽取，再用`prepare_document_consolidation.py --model cuc/qwen`生成Qwen专属输入。Qwen按DOC03→DOC01→DOC02完成首批回归后，才进入下一批9份。

`--force`只强制生成新的第二阶段试运行；旧原始响应不会删除，已有技术通过结果会先复制到`validated_history/`后再更新当前结果。

### 6.1 Qwen DOC03 熔断测试（2026-11-06）

使用`--model cuc/qwen`生成专属输入包（62个对话片段、12个候选、3组相邻对、33,067字符），并完成一次文档级归并：12候选→7文档事件，个人4、背景3、不确定0、待复核3。技术校验与逐字证据全部通过；`S0026`「我不在现场……我讲这些东西我不参加」被正确用作`NARRATED_CONTEXT`的范围证据，原内容熔断的核心成因已解除；复合候选`W001-E01`／`W002-E01`／`W004-E06`均正确拆分。
