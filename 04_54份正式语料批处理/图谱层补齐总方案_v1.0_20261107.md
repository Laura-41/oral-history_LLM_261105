## 一、验收目标（"能进入图谱"的硬标准）

以 `现行标注/neo4j_demo/import.cypher` 为唯一标尺：它 `LOAD CSV` **24 张表**（18 张标注表 + 6 张生平表），
建立 30 类关系。本方案交付物必须满足：

1. 51 份正式语料 × 选定模型线，逐份产出 **18 张标注 CSV**（表头与 `00_模板/` 完全一致）；
2. 全库合并产出 **6 张生平表**，生成 `05_合并与Neo4j/import/` 全套 24 张 CSV + `import.cypher` 适配版；
3. 通过 `现行标注/脚本/validate_annotation_bundle.py` 的全部校验（ID 唯一、外键、逐字偏移、
   每个事件恰有一条规范时间、`NEXT` 完整历史顺承链、`STAGE` 关系不跨一级事件、
   **所有原文片段均挂接且 `coverage_rate = 1.0000`**、JSON/CSV 行数一致）；
4. 新增校验：逐字证据命中、枚举封闭、按 `model_id`／`run_id` 留痕、双模型结果不混用、原文层 100% 覆盖；
5. 每条数据可回溯到 `document → segment → verbatim_text`，复核状态沿用 `MODEL_CANDIDATE / HUMAN_CONFIRMED`。

## 三、分层设计：L0 → L4

| 层 | 名称 | 产出 | API | 脚本 |
|---|---|---|:--:|---|
| **L0** | 确定性底座 | `documents / source_segments / source_attachments / coverage_audit / document_annotations / event_processes / event_participants / event_circumstances / event_next` 及一级事件骨架 | **零** | `scripts/graph_build_base_tables.py` |
| **L1** | 阶段与事件补完 | `process_stages / stage_next` + 一级事件 `result_state / factuality / boundary_note / confidence` | 每事件 1 次（可按文档合并） | `scripts/graph_run_enrichment.py --task stage` |
| **L2** | 实体与时间 | `entities / entity_mentions / entity_aliases / entity_relations / event_times / time_expressions` | 每文档 1 次 | `scripts/graph_run_enrichment.py --task entity_time` |
| **L3** | 人物生平 | `person_subjects / document_persons / life_episodes / life_episode_sources / life_episode_next / narrated_contexts` | 零（口径待裁决） | `scripts/graph_export_import.py:142-246`（20:0x 更正：原写的 `graph_build_biography.py` **不存在**） |
| **L4** | 图谱导出与验收 | 24 张 import CSV、Cypher 适配、校验报告、`GraphBuild` 记录 | 零 | `scripts/graph_export_import.py` + `scripts/graph_validate_bundle.py` |

### 3.1 两条不可让步的设计原则

1. **偏移量绝不由模型给**：`entity_mentions.start_offset/end_offset`、
   `time_expressions.start_offset/end_offset` 一律由脚本用 `verbatim_text.find(text)` **确定性计算并逐字回验**；
   模型只输出 `mention_text` / `raw_text`。找不到或多次出现即标 `NEEDS_REVIEW`，不猜、不硬写。
   `evidence_quote` 沿用现有逐字校验器（BATCH02 实测 87/87、80/80 全命中）。
2. **人工裁决优先**：`human_adjudicated/` 的范围判定覆盖 `validated_json/`，导入时以视图为准，
   并保留 `source_model_id / run_id / adjudication_reference`。`validated_json/` 一字不动。

### 3.2 枚举兼容映射（必须）

人工 `enumerations.json` 只有 `MODEL_CANDIDATE / NEEDS_REVIEW / CONFIRMED`，正式批次另有
`AUTO_VALIDATED / HUMAN_CONFIRMED / REJECTED`。导入时映射：

| 机器值 | 入库值 | 理由 |
|---|---|---|
| `AUTO_VALIDATED` | `MODEL_CANDIDATE` | 自动校验 ≠ 人工确认 |
| `HUMAN_CONFIRMED` | `CONFIRMED` | 研究者已裁决 |
| `NEEDS_REVIEW` | `NEEDS_REVIEW` | 原样 |
| `REJECTED` | 不入库 | 仅留痕 |

`data_role` 一律 `BATCH_APPLICATION`（六份 Demo 为 `WORKFLOW_DEMO`）；
`event_type` → `event_type_id` 映射为 `MATERIAL → MATERIAL_EVENT` 等六类；
`BEHAVIORAL → BEHAVIOURAL_EVENT`（注意人工枚举拼写）。

### 3.3 两套枚举词表不兼容（18:04 只读核实的新发现，须裁决 D6）

人工 Demo 与正式批次并非同一套封闭词表，**直接拼接会在导入时产生口径不一致**：

| 字段 | 人工 `enumerations.json` | 正式批次实测 | 处理建议 |
|---|---|---|---|
| `speaker_type` | 5 值 | 5 值 | ✅ 完全一致，直接沿用 |
| `role` | 17 值 | 实际出现 13 值，全部落在这 17 值内 | ✅ 兼容 |
| `event_type` | `MATERIAL_EVENT` 等 6 值 | `MATERIAL 159 / VERBAL 34 / RELATIONAL 4 / MENTAL 1` | 按 §3.2 加 `_EVENT` 后缀映射 |
| `review_status` | 3 值 | 5 值 | 按 §3.2 映射 |
| `circumstance_kind` | 5 值 `TIME/LOCATION/MANNER/CAUSE/PURPOSE` | 7 值，多出 **`DIRECTION` 44 条、`OTHER` 87 条** | 扩展枚举并保留原值；`DIRECTION` 的地点另建实体，不丢弃 |
| `segment_type` | 7 值 `EVENT_EVIDENCE/BACKGROUND/INTERVIEWER_PROMPT/NARRATOR_COMMENT/DOCUMENT_NOTE/OFF_TOPIC/UNCERTAIN` | 6 值 `ORAL_TESTIMONY/RECORDING_TIMESTAMP/INTERVIEWER_PROMPT/EDITORIAL_NOTE/BIOGRAPHICAL_PROFILE/UNCLASSIFIED_BODY`，**词表完全不同** | 按映射表转换；录音时间戳解析进 `start_timecode/end_timecode` |

建议映射：`ORAL_TESTIMONY→EVENT_EVIDENCE`、`INTERVIEWER_PROMPT→INTERVIEWER_PROMPT`、
`EDITORIAL_NOTE / BIOGRAPHICAL_PROFILE→DOCUMENT_NOTE`、`UNCLASSIFIED_BODY→UNCERTAIN`；
`RECORDING_TIMESTAMP` 片段本身标 `DOCUMENT_NOTE` 并保留原始值到 `normalized_text` 备注。

`import.cypher` 与 `validate_annotation_bundle.py` **都不校验枚举**（只校验 ID／外键／偏移／覆盖／链），
所以两种口径技术上都导得进去。推荐**扩展枚举 + 在 `GraphBuild.schema_version` 标注
`3.2+batch-application-ext` + 出具差异清单**，而不是为了对齐旧表丢掉 131 条真实环境成分。
此点列为 **D6** 交研究者裁决。

## 五、新增契约 `graph_enrichment_v1.0`

新建于 `02_Schema与提示词/graph_enrichment_v1.0/`（**新增子目录，不覆盖任何冻结文件**）：

- `graph_enrichment_contract_v1.0.md`：任务边界、两个任务的输入输出、提示词草案、校验规则、枚举与留痕要求；
- `graph_enrichment_output_schema_v1.0.json`：L1／L2 两个任务的 JSON Schema（封闭枚举、`additionalProperties: false`）。

契约要点：

- **L1 stage**：输入＝单个一级事件的 `event_name / core_process / event_type` + 其 `source_segment_ids` 的逐字片段；
  输出＝`event_enrichment`（结果状态／事实性／边界说明／置信度）与 `stages[]`（`stage_id / stage_order / stage_summary /
  process_text / evidence_segment_ids / evidence_quote / confidence`）与 `stage_next[]`（`logic` 封闭五值）。
  `stage_next` 不得跨一级事件；`stage_id` 格式 `<event_id>-P<NN>`，与人工一致。
- **L2 entity_time**：输入＝全文档片段（含脚注／编者注）+ 事件清单及其原始 TIME 环境；
  输出＝六张表内容；实体类型／子类型／别名类型／关系类型／时间精度／确定性全部取人工枚举封闭值。
- 两个任务都只输出合法 JSON，不输出 Markdown；`evidence_quote` 必须逐字复制；
  不得编造原文没有的日期、地点、身份、全名。
- **版本留痕**：每次调用记录 `prompt_version=graph_enrichment_v1.0`、`schema_version=v1.0`、
  `model_id / run_id / created_at / usage`，补登进 `01_实验配置/实验登记表.csv`（18 列不变）。

## 六、版本、可比性与双模型隔离

- **一级层规则完全不变**：窗口抽取提示词 v0.5、补充规则 v0.2、归并契约 v0.3、两个 Schema v1.0、校验器，
  一律不修改；BATCH02 的范围裁决与双模型对照结论继续有效，**不重跑 BATCH01／BATCH02 的一级层**。
- 新增层是**独立的下游任务**，以一级事件与其原文片段为输入，不改变一级事件边界；
  因此不存在「模型对比变成规则对比」的问题，方法章只需注明「阶段／实体／时间层为独立新增任务，一级层沿用原版本」。
- **D1（✅ 20:26 已裁 =1）**：「两套都留着，两个模型看两个图谱」。按 `model_id` **分别导出两套 import**、
  各自独立 `GraphBuild`，一级层保留双份对照；新增层按 D2 双跑，各自挂到本模型线。
  严禁把两个模型的候选拼进同一份文档。
  **P0（✅ 20:36 已定 A）**：两线 `event_id` 同名（Qwen `BATCH02-DOC01-DE001…005`、
  DeepSeek `…DE001…009`），而 `import.cypher` 用 `MERGE (e:EventNode {event_id:row.event_id})`，
  导入**同一个** Neo4j 会互相覆盖。研究者选 **A：两个独立实例／数据库，ID 保持原样不加前缀**；
  社区版单实例只有 `neo4j` 一个库，故落地为两个不同端口、不同 `data/import` 目录的实例。
  操作手册见 `05_合并与Neo4j/双模型双图谱_Neo4j使用说明.md`。
- **D2（✅ 20:26 已裁 =2）**：**新增层双跑** —— 研究者原话「两个模型都先跑着，目前算力支持就先跑」，
  撤回原「不双跑」推荐，直到另行通知。结果仍按模型目录隔离；一级层规则与提示词不变，
  双模型可比性不受影响（两条线各跑各的同一套任务）。
