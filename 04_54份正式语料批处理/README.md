## 三、跨窗口边缘处理

v0.5原文保持不改。批处理后处理程序执行以下确定性规则：

1. 窗口之间保留重叠片段，禁止完全无重叠切分；
2. 候选事件只要使用当前窗口最后一个有效受访者片段，且没有明确阶段性结果，就临时改为 `NEEDS_REVIEW`；
3. 该候选及其证据片段带入下一窗口，与下一窗口候选比较；
4. 主体、时间、地点、目标和证据连续时合并为一个事件；
5. 合并后重新生成事件名、核心过程和完整证据列表；
6. 到文档末尾仍无法确认完整性的候选继续保留 `NEEDS_REVIEW`，不得自动写成正式确认节点；
7. 原始模型响应永久保留，后处理只生成新文件，不覆盖原始结果。

这套处理将 `WINDOW-03` 的问题视为“跨窗口合并问题”，不再为此修改六类过程提示词或重新调试v0.5。

## 四、首批熔断条件

首批3份运行后，只检查以下必要条件：

- JSON可解析率为100%；
- 单事件Schema通过率不低于95%，未通过项全部进入人工复核；
- 每个输入片段进入事件证据或未分配片段，覆盖率为100%；
- 窗口边缘候选已标记并进入下一窗口合并；
- 未出现大面积把采访者提问、编者注或纯时代背景升级为受访者一级事件；
- 原始响应、Token、费用、错误和复核状态均已保存。

任一文档出现下列情况即暂停后续批次：JSON连续失败、片段覆盖不足、事件数量异常膨胀、边缘候选大量重复或背景误纳成批出现。暂停只阻止继续调用，不删除已完成结果。

## 七、首批运行方法

准备程序已经生成：

- `batch01_documents.json`：文档ID、原路径、片段数与窗口数；
- `batch01_source_segments.jsonl`：全部正文、人物小传和脚注片段；
- `batch01_manifest.csv`：12个窗口运行清单；
- `inputs/`：可发送给模型的12个重叠窗口；
- `source_extraction/`：DOCX无损提取结果与XML统计。

在已设置 `CUC_API_KEY` 的终端中，从`大模型标注1104`目录按文档顺序运行：

```bash
python3 scripts/run_formal_batch.py --model cuc/deepseek --document BATCH01-DOC01
python3 scripts/run_formal_batch.py --model cuc/deepseek --document BATCH01-DOC02
python3 scripts/run_formal_batch.py --model cuc/deepseek --document BATCH01-DOC03
```

程序逐窗口保存，已技术通过的窗口再次运行时自动跳过，可以断点续跑。任一窗口出现接口、JSON或Schema失败时立即停止；原始响应保存在`raw_responses/`，技术通过和边缘标记结果保存在`validated_json/`，相邻窗口的待比较候选写入`review_queue/`。
